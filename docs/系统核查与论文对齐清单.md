## 一、系统逻辑问题

按严重程度排序。标 ⚠️ 的是建议本次就修，标 💡 的是可记为"已知限制"。

### A1 ⚠️ 禁用用户 / 重置密码后，旧 JWT 仍然有效（高）

| 项 | 说明 |
|---|---|
| 现象 | JWT 是无状态的，签发后 24 小时内一直有效。管理员把用户禁用、或重置其密码后，该用户手里的旧 token 仍能正常调接口 |
| 位置 | `JwtInterceptor` 只校验签名与过期时间，不查用户状态；`UserServiceImpl.updateUserStatus` / `resetPassword` 只改库，不失效 token |
| 影响 | 演示时可能被问："禁用了个寂寞？" |
| 修法（二选一） | ① 拦截器里按 userId 查一次用户状态（每次请求一次查询，简单但增加 DB 压力）<br>② 用户表加 `token_version`，签发时写入 claims，校验时比对（改密/禁用时版本+1） |
| 建议 | 选 ②，改动集中在 3 处，且不影响性能 |

### A2 ⚠️ 商品新增/编辑缺少价格与库存的正数校验（中）

| 项 | 说明 |
|---|---|
| 位置 | `ProductServiceImpl.addProduct` 只校验名称非空、价格非空 |
| 问题 | 直接调接口可写入 `price = -1`、`stock = -999` |
| 前端 | `el-input-number :min="0"` 只能挡页面操作，挡不住接口 |
| 修法 | 补 `price > 0`、`stock >= 0` 两条判断（约 6 行） |

### A3 ⚠️ 取消订单恢复库存是「读-改-写」（中）

| 项 | 说明 |
|---|---|
| 位置 | `OrderServiceImpl.cancelOrder`：`product.setStock(stock + qty)` + `updateById` |
| 问题 | 与之前修掉的超卖是同一类问题：并发取消时可能少恢复库存 |
| 修法 | 改为 `UPDATE product SET stock = stock + ? WHERE id = ?` |

### A4 订单号可能重复（低）

| 项 | 说明 |
|---|---|
| 位置 | `generateOrderNo()`：`"ORD" + 毫秒时间戳 + random(0..999)` |
| 问题 | 同一毫秒内 1000 次随机碰撞才重复，概率极低但非零；`order_no` 有唯一索引，重复会抛 DB 异常 |
| 建议 | 可接受，记为已知限制；若要修，用 UUID 后缀或数据库序列 |

### A5 订单详情在 userId 为空时跳过归属校验（低）

| 项 | 说明 |
|---|---|
| 位置 | `getOrderDetail`：`if (userId != null && !order.getUserId().equals(userId))` |
| 问题 | 若某处调用传了 null，会直接放行。当前 Controller 始终传登录用户 ID，实际不可达 |
| 建议 | 可改为 `Objects.equals` 严格判断 |

### A6 分页 size 无上限（低）

| 项 | 说明 |
|---|---|
| 位置 | 各分页接口直接使用前端传入的 size |
| 问题 | 传 `size=100000` 会造成大查询 |
| 建议 | 统一在 Service 层夹到 1~100 |

### A7 💡 死代码：`UserService.updateUserRole`

`UserServiceImpl.updateUserRole` 没有任何调用方（`AdminController` 没有对应接口，前端也没有角色切换按钮）。
论文 4.4.6 明确写"不提供角色切换功能"，与实现一致 ✅，只是 Service 里留了个没人用的方法，建议删掉。

### A8 💡 README 声称"角色切换"，但无入口

`README.md` 用户管理一栏写了"角色切换"，实际没有。属文档错误，本次同步修掉。

**论文原文**：
> 注册成功后，后端会生成一个JWT令牌并返回给前端。

## 四、本轮修复记录（2026-11-18）

### A1 令牌撤销机制

- `sys_user` 新增 `token_version`（默认 1）
- 登录时把版本写入 JWT 的 `tv` 声明
- `JwtInterceptor` 每次请求额外校验：用户存在 → 未被禁用 → `tv` 与库中一致
- 改密、重置密码、启用/禁用 都会让版本 +1，旧 token 立即失效

**实测**：

| 场景 | 结果 |
|---|---|
| 正常 token 访问购物车 | 200 |
| 管理员禁用后同一 token | 401「账号已被禁用，请联系管理员」 |
| 管理员重新启用后同一 token | 401「登录状态已失效，请重新登录」 |
| 用户改密后旧 token | 401「登录状态已失效，请重新登录」 |
| 新密码登录后新 token | 200 |

> 兼容说明：升级前签发、不含 `tv` 的旧 token 仍按版本 1 处理，最多存活到过期。

### A2 商品价格与库存校验

`addProduct` / `updateProduct` 增加：价格必须 > 0、库存不能为负。

**实测**：`price=-1` → 「商品价格必须大于 0」；`stock=-5` → 「商品库存不能为负数」。

### A3 取消订单恢复库存

`ProductMapper` 新增 `restoreStock`（`UPDATE ... SET stock = stock + ?`），替换原来的读-改-写。

**实测**：库存 18 → 下单 2 件变 16 → 取消后回到 18。

### A7 死代码清理

删除 `UserService.updateUserRole` 与其实现（无任何调用方）。
