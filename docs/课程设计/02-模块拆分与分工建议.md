# 模块拆分与 5 人分工建议

> 用途：给 5 位组员分配模块，并直接填进报告「第3章 项目组成员分工计划」
> 代码规模：后端 94 个 Java 文件（12 个 Controller、9 个 Service）、前端 24 个 Vue/JS 文件
> 工作量单位：人日，仅用于比较轻重，不是真实工时

## 二、5 人分工建议

> 按「职责域」划分，每人一条完整链路，便于各自写第 5 章总结。
> 总工作量 78 人日，人均约 15.6 人日。

| 角色 | 负责模块 | 工作量 | 一句话职责 |
|---|---|---|---|
| **组长（你）** | A1 A2 A3 + D4 D5 D6 + G1 | 18 | 架构与认证底座、推荐算法核心、论文统筹 |
| **组员 1** | B3 B4 B5 B6 B7 + F5 | 14 | 交易主链路：浏览 → 购物车 → 地址 → 下单 → 订单 |
| **组员 2** | C1 C2 C3 C4 C5 C6 + A4 | 13 | 管理后台六个页面 + 前端公共组件 |
| **组员 3** | D1 D2 D3 D7 D8 + F4 | 14 | 推荐工程：埋点、画像、热度、大模型标签、推荐位与评估 |
| **组员 4** | B1 B2 + E1 E2 E3 E4 E5 + A5 + F1 F2 F3 + G2 | 16 | 注册登录与客服助手、测试体系、部署 |

### 分配合理性

- **不交叉**：每人负责的模块互不重叠，避免"改同一个文件"
- **可独立陈述**：每人都有完整功能链路，第 5 章总结好写
- **轻重可调**：若组员 4 偏重，可把 F1（单元测试）整体转给组员 1，或把 B2 转给组员 1

### 如果想换一种分法（按技术层）

| 角色 | 负责 |
|---|---|
| 前端 A | 用户端全部页面（B3-B7、B1、B2 的前端） |
| 前端 B | 管理端全部页面（C1-C6）+ 客服抽屉 |
| 后端 A | 认证、商品、购物车、地址、订单（A2、B1-B7 后端） |
| 后端 B | 后台管理接口、轮播图、客服助手后端 |
| 组长 | 推荐模块 + 架构 + 测试 + 文档 |

> 两种分法都行。**推荐第一种**（按功能域）：每个人都能讲"我做了哪些功能"，答辩问答不易被问穿；第二种容易出现"我只写了增删改查"的尴尬。
