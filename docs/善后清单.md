## 四、P0-3 数据库与 Docker 重置

### 为什么必须重置

新方案会把 `category` 从扁平表改成层级表（`parent_id/level/path`），并把商品重新归类到「书法」域。
旧数据（7 个宽泛分类 + 19 件综合收藏品）与新分类体系**无法自动映射**，与其写迁移脚本，不如直接重建。

### 重置前先备份（建议但可选）

```bash
docker exec shopping-mysql mysqldump -uroot -p123456 --databases shopping \
  > ~/shopping-backup-$(date +%Y%m%d).sql
```

### 重置步骤

```bash
cd /home/emperor/Project/shopping-system
docker compose down -v          # 连数据卷一起删
docker volume ls | grep shopping   # 确认卷已消失
# —— 等新 schema 改完后再启动 ——
docker compose up -d
docker logs -f shopping-backend # 看 DataInitializer 日志
```

### 重置后会丢什么、需要重跑什么

| 数据 | 说明 | 重跑方式 |
|---|---|---|
| 用户 / 商品 / 分类 / 轮播图 | `DataInitializer` 首次启动自动重建 | 自动 |
| 200 个模拟用户 + 9241 条行为 | 丢失 | `python tools/generate_sim_data.py` |
| 商品标签（93 条） | 丢失 | 管理端 `POST /api/admin/recommend/extract-tags?force=true`（需 LLM Key） |
| 用户画像 / 热度 | 丢失 | 定时任务或手动触发重建 |
| 测试订单 | 丢失 | 不需要 |

> 如果打算「先改分类再重置」，那这一步放到新窗口的 P4 阶段；如果现在就重置，新窗口要再重灌一次数据。**建议跟分类改造一起做，只重置一次。**

### 验收

- [ ] 13 张表齐全（`SHOW TABLES`）
- [ ] 分类为空壳或新建的层级数据
- [ ] 前台能打开（http://localhost:8000）
- [ ] `admin/123456` 能登录
